# Roster — v0.109.0

The lead is the `lead` skill (`/kru:lead`, runs in the main thread). It delegates to the specialists below and to built-in agents (`Explore`, `Plan`) and skills (`/code-review`, `/tdd`, `/diagnosing-bugs`, `/verify`, `/run`). Every specialist follows **official sources first** (`SOURCES.md`).

## Scope — where this team stops
Engineering-led, cross-functional at the top. The team spans **product-development**: engineering (core) + design + the thin upstream layer that feeds the build. **The user is the PM** — there is no product-management function, no roadmap, and no prioritization framework in the team; what-to-build-next is the user's call, and the team formalizes and executes it. The upstream layer is two things: the lead's **`brief` verb** (grill → a change-shaped `brief.md` incl. the commit/PR cadence, inline) and `planner`, an **upstream adapter** that turns that brief into a spec/ticket graph handing *into* engineering. Neither runs a separate org. `ux-designer`/`graphic-designer`/`conversion-copywriter` feed the build — the last of those writing a marketing page's argument and strings *before* it is designed or built; growth on shipped pages is user-invoked — `/seo-review` for technical SEO/AEO, `/copywriting`/`/copy-editing`/`/cro` for conversion copy on what already ships.

The team stops at product-development. **Company functions are out of scope and stay uninstalled**: sales, marketing **channels/campaigns** (email, ads, social, SMS, PR, outreach, referrals), finance, legal, support, ops/HR. The line is *what ships in the build vs. what runs as a channel*: on-page conversion copy + CRO on the pages the team builds is product-development — the `conversion-copywriter` seat writing a page's argument before it is built, and the user-invoked `/copywriting`/`/copy-editing`/`/cro` passes over what already ships — the same way technical SEO on those pages is (the user-invoked `/seo-review` pass); a campaign run through a channel is not. This is the same discipline the vendoring rule runs on (vendor only the upstream skills that feed the build; don't drag in whole plugins). Adding a seat is fine (see *Growing the team*); adding a *business function* is a different product — don't.

## Model tiers
Every non-lead seat is pinned to an explicit `model:` in its frontmatter — no seat inherits the session model. Policy — spend on correctness (implementers, judgment-heavy specialists, the hardest reviewers), economize where the work is pattern-matching/checklist application.

**Why pinned instead of inherit**: under `inherit` the team's cost scales with the *lead's* tier rather than each seat's actual need — a Fable 5 (premium, $10/$50) lead session drags all 25 subagent calls onto Fable pricing, the mechanical ones included. Pinning decouples them: the lead runs on any tier while specialists cost what their work requires.

**Why full model IDs instead of the `opus`/`sonnet` aliases**: the aliases float to whatever the current generation resolves to, so an install's behavior silently changes under it. Every seat names `claude-opus-5-5` / `claude-sonnet-5` outright — reproducible across machines, plans, and the web VM. Cost: an install whose plan or provider (Bedrock/Vertex/Foundry) doesn't expose those IDs must swap back to the alias.

**Effort is pinned where the output *is* a judgment, and inherited everywhere else.** `effort:` in agent frontmatter takes `low`|`medium`|`high`|`xhigh`|`max`. `code-reviewer`, `architecture-reviewer`, `ux-auditor` and `planner` pin **`high`**: what they return is a finding set or a decomposition, so how hard the model looked *is* the product — a session dropped to `medium` silently shortens the list, and a short list reads exactly like a clean diff. The sonnet tier (`toolchain-engineer`, `vercel-perf-optimizer`, `dispatch-auditor`) pins **`medium`**: checklist application against documented conventions, which a high-effort session shouldn't pay premium thinking for. Every other seat inherits the session level deliberately — unlike model tier, effort tracks how hard *this change* is, and a builder executing a settled spec should move with the session rather than against it. `xhigh`/`max` error out when thinking is disabled, so no seat names them.

**Prompt cache TTL: `1h` on the seats the lead re-dispatches.** `experimental.cacheTtl: "1h"` on the eight builders, `python-developer`, `test-writer` and `code-reviewer` — the seats one lead run calls repeatedly, minutes apart. A 1h cache write costs more than a 5m one and is repaid on the second dispatch, so the seats called once per change (`planner`, `ui-designer`, `stripe-specialist`, `paypal-specialist`, `chariot-specialist`, `nowpayments-specialist`, `quickbooks-specialist`, `zapier-specialist`, `better-auth-specialist`, the platform seats) stay on the 5m default where a single write is the whole story. A user-level `subagentPromptCacheTtl` setting overrides the frontmatter, and `1h` is ignored while a Claude subscription is in overage.

Fable 5 is the premium tier ($10/$50, above Opus 4.8's $5/$25). Don't pin any seat to it. Want the whole team a tier cheaper (or pricier) across the board? Re-pin every `claude-opus-5-5`/`claude-sonnet-5` line above in one pass rather than reverting to `inherit`, which reintroduces the lead-tier coupling above.

Everything else it used to do went to the seat that owns it: tap targets are a WCAG criterion (`accessibility-reviewer`, which drives the same browser), and a value outside the token file is a grep — now the repo's own conformance gate, a hundred times cheaper there than in a browser. Contrast went further out still — it is **the design's**, audited by no seat, since re-deriving it downstream re-opens a decision whose only fix is a redesign. What's left of measurement is **one number inline where it settled a real doubt** — never a table, which was mostly the pass restating what the token file already said.

The design gate is the user's glance; the way to improve on it is to render what a glance never reaches, not to buy a second, worse one.

Report-first by layer; minimal markup fixes applied only when the user asks. It stays **user-only** even though the three screen passes carry seats — technical SEO is judged against a page's goals, not a checkable rule the lead can gate on; CWV stays `vercel-perf-optimizer`'s.
- **`brief`** (`skills/brief/`) — **self-contained user-invoked planning skill**, promoted off the lead's verb list in v0.51.0 for the reason `todo`/`issue` were: it is typed, it writes one file, and it needs none of routing, the handoff contract, the gates or reconcile — so typing it charged the whole orchestration body to write one file, and the verb form cost the lead a `brief`-versus-task disambiguation paragraph that an address deletes. `/kru:brief <subject>` grills the user (`/grilling`) and then **persists a change-shaped `brief.md`** — `Change` · `Why now` · `Blast radius` · **`Landing plan`** (the cadence — commits are the steps; a PR split means an environment boundary or a partial ship) · `Decisions resolved` · `Non-goals` · `Done when` — into the user-level plan store, rewritten in place on each re-grill. It replaced the `/pm` pass: **no roadmap, no horizons, no priority framework** (the user is the PM), and ship cadence moved *onto the lead* because the lead is the only seat holding both the intent and the codebase seams. That same rationale keeps it off a standalone skill: it needs the `Explore` map and the grill in one head, which a standalone skill would have to rebuild cold. It's named `brief` for the file it writes, and to stay clear of Claude Code's own plan mode. A bare `lead <task>` still grills by judgment — it just doesn't persist. Hands the brief to `planner`; its other half is `TODOS.md` capture.
- **`todo`** / **`issue`** (`skills/todo/`, `skills/issue/`) — **self-contained user-invoked capture skills**, promoted out of the lead's verb list: `/kru:todo <the thing>` logs something the user wants but doesn't want done now into the store's `TODOS.md` as a line carrying `value` and `effort` (`1`–`5`, `~n` when the number is the session's proposal rather than the user's — the pair `todos` ranks on, and the `plan` field now holds the effort slug `effort` used to), and `/kru:issue <what's wrong>` opens `issues/<slug>.md` from what they just said, with every field it didn't investigate written as `_not investigated_` **in the file** so a cheap stub can never read as a finished write-up. Both return straight to whatever was in flight. They're the user's front doors to the two artifacts Step 4.5 already sweeps into, for when no task is running to sweep from; `brief` reads both back during the next grill and the user (the PM) decides what gets pulled into scope. The store's three-way split routes them: **wrong → `issues/`, wanted → `TODOS.md`, unformed → `notes/`**.
  **`todo` expands from loaded context, never from a fetch**. Logged mid-session — the file was just read, the error just seen, the decision just made — the line carries up to two sub-bullets of what the writer already knew (`file:line`, the constraint, why it's deferred). Logged cold, it's the user's sentence and nothing else. The rule is **cost, not usefulness**: already-loaded context is free and evaporates if unwritten, but no `Explore`/grep/file-open is ever justified to enrich a line — that's the task the user just declined. Expansion adds detail, never commitment: past the two numbers, no triage, no scheduling, no scoping into the current effort — and the numbers obey the same rule, taken from the user's own words, or estimated and written `~n` — a proposal the confirmation hands back, never fetched for. The rule is shaped around the common case — a *deferred want* raised mid-build, where the session already holds exactly the context that makes the line worth re-reading later.
  **Both are `disable-model-invocation`, and that's the design.** A user-invoked skill can't be reached by the agent *or by another skill* (`writing-for-agents` → `SKILL-MECHANICS.md`), so the lead can't fire them — which costs nothing, because the lead's own capture channel is the Step 4.5 sweep, written with the code already in context. What it buys is the thing that made the split worth doing: **zero standing context load**, where three model-invoked descriptions would have been permanently loaded in every session to save lines that only load when `lead` runs. It also enforces the no-autonomous-triage rule structurally rather than in prose — an agent that *can't* fire `/idea` can't autonomously triage a thought into work nobody asked for.
  **`todos` / `issues` are the working halves** (`skills/todos/`, `skills/issues/`) — same four steps each: **reconcile** every entry against the code (a want is done · archived · open; a defect is fixed · moved · open), **score** what's unsized (`value`/`effort` on a want, `effort` beside the filed `severity` on a defect — `~n` until the user confirms), **propose** a batch of `effort: 1`–`2` entries across different seams off the ranking (`value ÷ effort`; severity then effort; ties newest first), and **gate** — one message, then wait. Nothing is written before the user answers: confirmed-done lines and confirmed-fixed files are deleted, confirmed digits go bare, and each accepted entry reaches exactly one named outcome — *built/fixed* (one commit each, its entry deleted at Step 4.5), *already done* (deleted, nothing built), or *bigger than it says* (rescored in place, parked or handed to `brief`, never half-built). That gate is the whole guardrail: the order is arithmetic, the batch is a proposal, what gets built is the user's — the same call `brief` hands them. This is the exit `TODOS.md` never had (`issues/` was always emptied by fixes) and the only place a filed number meets the codebase. Singular writes one, plural works them — one word per artifact. `disable-model-invocation` for the write halves' reason plus one of their own: an agent that can fire `/issues` can pull the defect list into a task nobody pointed it at.
  **`briefs` is `brief`'s working half** (`skills/briefs/`). Step 4.5 ticks a brief as slices land, and nothing else ever checked those ticks against what shipped — so this is the same reconcile-then-gate shape pointed at `plan/`. It departs from `todos`/`issues` twice, both on `TRACKER.md`'s word: it proposes no batch and no rank, because efforts are never ranked against each other; and it reconciles only a brief's bookkeeping (ticks, paths, ticket status), leaving the account to `/kru:brief`, because `Decisions resolved` is the user's to re-decide. `disable-model-invocation` for `issues`' reason: an agent that can fire it can resume an effort nobody pointed it at.
- **`landed`** / **`comment-fix`** (`skills/landed/`, `skills/comment-fix/`) — **self-contained user-invoked change-hygiene skills**, the bookends around a landing. `/kru:landed` closes a change out: it reads `state: MERGED` off the PR rather than asking git, because a squash or rebase merge leaves none of the branch's SHAs in the base — `git branch -d` refuses it and `git log base..branch` still lists every commit, so the `-D` people reach for is being made blind. It guards on a dirty tree, on local commits past the PR's `headRefOid`, and on a base that needs more than a fast-forward, then syncs and prunes. `/kru:comment-fix` audits one target (working tree · path · branch · PR) against the standard the user's own `CLAUDE.md` sets — lowercase, for the next reader of the code, never for the prompter — and carries that standard itself, since a plugin lands in repos whose instructions don't state it. Its bound is the target: a *diff* target audits what the change wrote, not every comment in the files it grazed, and its completion criterion is checkable — every hunk in the resulting diff is a comment line. Both are `disable-model-invocation`, same reasoning as `todo`/`issue`: a branch delete and an unasked-for restyle are exactly the two things the agent should not be able to start on its own.
- **`doc-fix`** (`skills/doc-fix/`) — **self-contained user-invoked change-hygiene skill**, `comment-fix`'s sibling for human doc prose: `/kru:doc-fix` audits a target's `README`/`CONTRIBUTING`/`DEPLOY`/`docs/` against the house standard — keep the traps, the consequences, and what no run can teach; point at the canonical file for everything else — cutting negatives, run-output narration, code restatement, and era-bound status. Agent-consumed documents (`AGENTS.md`, `CLAUDE.md`, skill/agent definitions) stay `writing-for-agents`' lane. Same checkable completion criterion: every hunk in the resulting diff is doc prose. `disable-model-invocation` for the same reason as `comment-fix`: an unasked-for doc restyle is exactly what the agent should not start on its own.
- **`prose-fix`** (`skills/prose-fix/`) — **self-contained user-invoked change-hygiene skill**, the third `-fix` verb: `/kru:prose-fix` audits the strings a target renders to the user — JSX text, `placeholder`/`aria-label`/`alt`, i18n source-locale entries, form-action errors, toasts, email templates — against a standard it *points at* rather than restates: `ui-patterns`' text-and-icons group and `ux-copy`. It cuts UI narration (the line describing what the screen already demonstrates), outcome claims the code can't hold, a stored name at a sentence's head, vague actions, a field error restating its label, and the AI tells and em-dashes `doc-fix` bans, with the same binary grep check. Two things distinguish it from its siblings: a cut narration line is, per the `ui-patterns` rule, a defect report on the control, and the control is code — so the pass cuts the line and names the control's `file:line` in the report; and a string has a shadow — the test literal that pins it — which gets the same edit, the one non-UI file the pass moves. Log lines, developer `Error` messages, fixtures, and marketing routes (`copy-editing`'s) stay out. `disable-model-invocation` for the same reason as `doc-fix`: an unasked-for copy restyle is exactly what the agent should not start on its own.
- **`text-fix`** (`skills/text-fix/`) — **self-contained user-invoked router that executes**, and the single entry point over the text passes: `/kru:text-fix` resolves a target once, classifies every file it resolved to, and runs each class that fired under its own standard. It exists because the passes were never four jobs — a real target carries more than one class, and running them one at a time resolves the same target four times and re-reads the same files four times. The cut it buys is the **hand-off**: the sibling files refer work to each other mid-hunk (*a hit inside a comment is `comment-fix`'s; leave it and say so*), and here that resolves to *fix it under the other pass* instead of to a line in a report nobody acts on. It **restates no rule** — every row of its classification table is a pointer at the file that owns that class, `comment-fix` and `prose-fix` and `doc-fix` for the three that have a skill, and `setup`'s seven bars plus `writing-for-agents` for the agent-doc rows, which are a standard with no pass of their own. Those two rows are why it routes by reading rather than dispatching, and the mechanism holds for the skills too: all three siblings are `disable-model-invocation`, so nothing but the human can fire one, and a router here **reads their `SKILL.md` off disk and runs it** (`skills/writing-for-agents/SKILL-MECHANICS.md` → *Router skills*, whose hint-only router this is the executing form of). Two rules make the merge safe: it runs **pass by pass, not file by file**, since two cut-lists read at once blur both; and where two standards disagree — the em-dash ban, which exists because a human reads that text — **the file's class decides**, so a `—` in `README.md` goes and the same character in `CLAUDE.md` stays. Its completion criterion is the union of the four: every hunk is a comment line, a rendered string, doc prose, or agent-doc prose, with frontmatter `name` and `disable-model-invocation` held as API.
- **`reflect`** (`skills/reflect/`) — **self-contained user-invoked look-back skill**, and the retrospective counterpart to the review gates: `/kru:reflect [<pr> | <branch> | <commit> | everything]` runs in two phases. **Look back** reads the repo's **sheet** for the roster, assigns every file in the target to the seat that owns its stack, and fans the lot out in **waves** — parallel inside a wave, the browser- and suite-bearing seats in a wave of their own — read-only, builders included. The premise is that the seat that wrote a lane knows what it got wrong there: a generic reviewer reads a migration and sees code, while `postgres-architect` reads it against the lock it takes. Two properties keep that phase affordable — **every seat runs in its own context**, and **every seat writes its record to disk** and returns a ranked shortlist of ten plus a pointer, so the lead never ingests a subsystem it isn't routing; the reports stay closed, because reading one is the context balloon the waves and shortlists exist to avoid. Three things in its brief are its own, past `lead` Step 3's seven items and `gates.md`'s report path: the lane and only the lane, **read-only stated** (a builder seat has write tools and a bias toward using them), and what the work was for, so a seat catches *built the wrong thing* and not only *built wrong*. **Then fix it** is why the first phase is worth running: findings merge, split by `TRACKER.md`'s three-way rule (**wrong → `issues/`, wanted → `TODOS.md`, unformed → `notes/`**) so that **only the wrongs are candidates**, and then take the three cuts in order — **scope** draws a line across the severity ranking and files what falls below it, **slice** cuts tracer bullets that each land alone in dependency order, and **partition** sends each slice to one seat by the same grouping rule, since the seat that *reported* a finding is not always the one whose file it is. Sliced work that won't fit one context goes to `planner` (Step 2.6) rather than being improvised. A **gate** sits between the plan and the store: nothing is written or dispatched before the user answers, because the whole output is a claim about work they already accepted. Then the picked slices land as ordinary builds under Step 3 and 4, each brief naming the finding it closes, and each landed fix deleting its `issues/` file. `disable-model-invocation`: an unasked-for fan-out across the roster, followed by edits to landed work, is exactly what the agent should not start on its own.
- **`update`** (`skills/update/`) — **self-contained user-invoked maintenance skill**: `/kru:update [claude|vendored|libs]` sweeps the three grounds that move under the plugin — the Claude Code releases above the mark (`claude.md`), each vendored copy's provenance sha against upstream's head (`vendored.md`), each first-party skill's `Reproduced on` pin against the registry and the release notes for the range (`libs.md`) — and returns a verdict per change with the file it lands in. **The thing on disk is the authority and the announcement is the lead**: a candidate frontmatter key is confirmed against the zod schema in the binary (`claude plugin validate` passes on any unknown agent key, so it answers a different question), a subcommand against its `--help`, an upstream commit against its diff, a release note against the identifiers the skill claims. It writes `reviewed.md` and nothing else — one section per ground, declines recorded with their reason so the next sweep doesn't re-litigate them; wiring an adoption is `/roster`'s, a re-sync or re-verification is `/roster author <name>` → *Refresh*. `disable-model-invocation` for the same reason as `todo`/`issue`: a sweep the agent can fire is a network fetch and a prompt-text rewrite nobody asked for.
- **`setup`** (`skills/setup/`) — **self-contained user-invoked bootstrap skill**, and the plugin's other direction: `/kru:setup` derives a repo's standing answers once — seat pointers, the **conditional skills** this repo answers *yes* to (the library-choice check a seat re-runs on every dispatch, and skips silently), the seats this repo has no footing for, and whatever the repo's own docs leave unwritten (the gate that closes its token file, **what a test run costs**) — and writes them into that repo's `.claude/CLAUDE.md` in that file's own idiom (`sheet.md` carries the fields and two renderings). What lands is **deliberately thin — a pointer at `kru:lead` plus the sheet, ~400 tokens** — on the split that decides everything here: *how the team works* is needed only once work starts, so it loads on demand from the plugin, while *who is on the team here* is what tells a session there is a team at all, so it is the only part that goes ambient. The pointer only fires because `lead` keeps a `description`; a user-invoked skill is unreachable by the agent and by other skills, which would make that line decorative. The sheet loads on every session in that repo with nothing typed, so routine work runs off the answers and `lead` loads only for what a sheet can't hold (greenfield, `planner`, a stack with no seat). Two rules carry it: **every derived line cites what it came from**, so a re-run can tell a stale line from a live one, and **the repo's own `CLAUDE.md`/`AGENTS.md` is a source of truth** the block references rather than restates. The citations are what make a re-run an edit rather than a second copy — a derived line can be told from the repo's own — and one HTML-comment stamp is what makes the sheet a cache instead of a fork; re-running is the only update path, since the sheet is a function of *(plugin version × repo state)*, so re-deriving settles a repo that moved and a plugin that moved alike. It writes to a **checked-in** file, so it shows the whole diff and waits. `disable-model-invocation` for the same reason as `todo`/`issue`: editing a repo's committed instructions is not something the agent should start on its own. Its counterpart upstream is `/roster learn`, which routes a one-engagement preference to a repo's sheet and a two-engagement one into the plugin (`PREFERENCES.md`).

4. Recompute the agent count (`ls agents/*.md | wc -l`) into `plugin.json` + `marketplace.json`; bump `VERSION`, `plugin.json` `version`, and the header above (minor bump for a new agent).
5. `git add -A && git commit && git tag vX.Y.Z`.

Adding a **skill** is the smaller change (`/roster author`) and carries its own entry bar: a skill is **recipes earned by working with the thing**, never a restatement of docs the stack's `SOURCES.md` row already serves — order that matters, defaults with the reason attached, traps, and what to leave out. Derivable-from-the-source-in-the-moment is a lookup, not a skill.

`/roster` also does the inverse (`retire`), authors skills (`author`), and reports wiring **drift** (`audit`) — e.g. the agent count in `plugin.json`/`marketplace.json` disagreeing with `agents/*.md`.

Versioning: semver-ish. New agent or capability → **minor**. Prompt tweaks/fixes → **patch**. Breaking reorg of the orchestration contract → **major**.
