# Official Sources Registry

**Team principle — official sources first.** For any framework / library / API / CLI / cloud-service specifics, no agent answers from training data. Resolve it through the official MCP, skill, or plugin below. Prefer first-party sources over third-party blogs. Training data is a starting hypothesis to verify, never the answer.

**Corollary — a repo-authored skill is the layer the docs can't serve.** Docs are hammer and nails; they don't make the house come out right the first time. So a skill here carries **recipes and patterns earned by working with the thing** — order that matters, defaults chosen after the obvious one failed, cases where correct-by-the-docs is wrong in practice, popular advice that's wrong. Anything derivable from the official source in the moment is a **lookup, not a skill**, and stays in that stack's row below. A skill that restates docs ages out of sync and then outranks the source while stale — which is why quickstart-grade community packs get rejected rather than vendored (see the Drizzle row). Authoring rules: `skills/roster/author.md`.

Agents: consult the row for the stack you're working in. The PM (the `lead` skill) uses this table to route and to wire any newly-minted specialist to its official source.
