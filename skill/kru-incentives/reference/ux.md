# UX — the user pays for every step

A user takes a step when what it gets *them* exceeds what it costs them, at the moment they meet it. What the step is worth to the product never enters that sum. Users arrive to get something done now and skip whatever doesn't advance it, even when learning it would pay later (Carroll & Rosson 1987), and they take the first option that is good enough rather than the best one (Simon 1956).

- **Put the value before the ask.** An ask placed before the user has seen what they get is priced against nothing, and it loses. Signup, permissions, profile fields and preferences move to after the first payoff — account creation at the save, the location prompt at the map.
- **A required field with no payoff to the user gets fabricated.** Make it required and the user pays the cheapest price that clears validation: `a@a.com`, `asdf`, `000-000-0000`, the first option in the select. The column fills and the data doesn't exist, and nothing downstream can tell. Make it optional, move it to where it pays the user, or derive it. `ux-principles` carries the code signal.
- **The default is the decision for most users.** Most people keep whatever is preselected — opt-out organ-donor countries run at many times the consent rate of opt-in ones (Johnson & Goldstein 2003). Choose the default as the outcome you want for the majority, because it will be; choice architecture is never neutral (Thaler & Sunstein 2008).
- **The first plausible option absorbs the traffic.** Put the intended path first, most prominent and shortest; a path the design prefers but places second is the path few take.
- **Place the common case on the convention.** Where nothing on the screen says what to do, users converge on the familiar spot (Schelling 1960) — a primary action where primary actions usually sit, a logo that goes home. A novel placement charges every user a search.
- **The 80% case gets the short path; the exception gets a reachable, longer one.** An exception's branch inside the common path taxes everyone for the few.
- **A rule that costs every user daily for a harm few ever see gets routed around.** Forced rotation, composition rules and repeated confirmations produce the sticky note, the `Password1!`, and the reflexive *OK*. Users reject that trade rationally (Herley 2009), so the rule buys less than it looks like it does. Put the cost where the risk is.
