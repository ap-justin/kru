# audit — report roster drift

Read-only. Assert every point of the wiring map (`SKILL.md`) agrees across files, then report a table: **check → OK / DRIFT → fix**. Report only; hand fixes to `hire`/`retire`, or apply on the user's say-so.

## Assertions
1. **Count** — `ls agent/kru/*.md | wc -l` equals the "N specialist subagents" number in **both** `package.json`'s description and `README.md`.
2. **Version** — `VERSION` equals `package.json` `version` equals the `README.md` plugin entry's `version` equals the `ROSTER.md` `# Roster — vX.Y.Z` header.
3. **Full registration** — every `agent/kru/*.md` has (a) a `ROSTER.md` *Current specialists* row, (b) a `scripts/port.mjs` → `SEATS` tier or the `coding` default, (c) a `{KRU_HOME}/kru/references/routing.md` routing row **or** *Step 4* review wiring **or** a `ROSTER.md` row marked **user-invoked** (user-triggered — via a thin invoker skill or direct spawn; absent from `lead` by design) **or** a `ROSTER.md` row marked **hook-invoked** (fired by the plugin (`plugin/kru.ts`); absent from `lead` by design — assert its named hook scripts exist under `hooks/`), and (d) a `SOURCES.md` row **or** an explicit stack-agnostic note.
4. **No orphans** — every `ROSTER.md` specialists row and every `lead` routing row names a real `agent/kru/*.md` file.
5. **Model agreement** — every seat pins an explicit **full ID** (`opencode/<model>`, never a floating alias) and it comes from `scripts/port.mjs` → `SEATS` rather than a hand edit.

7. **Countable claims in `ROSTER.md` prose** — every number a skill row asserts about its own files is re-derived, not trusted: corpus entry counts (`grep -c "^## " skills/<name>/reference/*.md`), `Detect:` tier breakdowns, group counts, verified-URL counts. Re-count rather than reading the sentence: the last row to carry a stale count carried it across three releases and was still wrong when the skill was deleted.

8. **Context load** — nothing in opencode reports it, so measure it: every frontmatter `description` across `agent/kru/*.md`, `skill/kru-*/SKILL.md` and `command/kru/*.md` loads on every turn whether or not the thing fires, and that total is the budget a new seat or skill spends against. `grep -h '^description:' agent/kru/*.md skill/kru-*/SKILL.md command/kru/*.md | wc -c`. Report it with the delta since the last audit, and name the longest few when it grew — an over-long description is drift the count check can't see. `opencode agent list` cross-checks assertion 1 from the loader's side: a seat it doesn't list is one `package.json` claims and opencode never loaded.
9. **Floor** — README → *Requirements* names a minimum opencode version, and it holds only while it covers the newest frontmatter key the seats actually use. Derive it, don't read it: collect the keys across `agent/kru/*.md` and `skill/kru-*/SKILL.md` frontmatter, and the floor is the release that shipped the newest one (`skill/kru-update/reviewed.md` records which release that is). A key below the floor is silently ignored on an older CLI rather than erroring, so the seat runs and the setting doesn't — drift with no symptom.
