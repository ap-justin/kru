# Review and verify — which gates a slice earns

Loaded by `lead` when the branch is live.

**A build return from a seat carrying Block O, with no `Return pass:` line, is unverified** — that line is the seat's own read-back of the finished slice (`${CLAUDE_PLUGIN_ROOT}/skills/roster/shared-blocks.md` → Block O), and its absence is the one defect every gate below is blind to, because a pass that never ran leaves no diff. Ask that seat for it — same-task reuse, inside the 2-loop cap — before the rest of Step 4 runs. The brief never asks: the block rides in the seat prompt, and re-authoring it there is the restatement Step 3 refuses. The one seat Block O exempts (`test-writer`) never carries the line; its own bound — a green suite — is its verification.

**Done is judged on evidence, not the return's account of itself.** Before a build return is ready for Step 5, pair every behavior on the list you handed down (your grill, or `brief.md`'s `Done when`) with its proof — a test name, a command's output, a count, from the return or from your own scoped run. A behavior with no proof beside it is unbuilt until shown otherwise: send it back to that seat (same-task reuse, inside the 2-loop cap). Pairing is for accurate handoff — **evidence is not PM acceptance**; Step 5 marks each criterion with proof or **unproven** and the PM decides.

**Builder verification** is whatever a user could not confirm by using the product alone: tests, lint, typecheck, edge cases, and data/backend behavior — including in-process checks (MCP tools from a test, Hono's `app.request()`, migration and DB checks, and the repo's other non-interactive CI). **PM acceptance** (Step 5) is what a user could verify by using the product: rendered screens against the design spec, accessibility a user hits, multi-screen flows, and running the app to see it behave. The lead does **not** dispatch `code-reviewer`, `architecture-reviewer`, `visual-reviewer`, `accessibility-reviewer`, or `ux-auditor` in Step 4 — those seats and skills run only when the **task names** them explicitly (`references/routing.md`).

**A finding enters the fix list only when its trigger happens in normal use** — an ordinary user action, a provider's documented retry or redelivery, concurrency the real crons, retries and staff produce, data a UI or an import can create, an ordinary attacker. One that needs a convoluted trigger is dropped, one counted line in the report at most, never ranked or filed: our own keys or config failing once set (a key a *user* enters still gets validated and a clear error), a provider breaking its own docs, one human action racing itself within milliseconds, data no path can create, an attacker already holding our secrets or database, a vendor outage cited to justify new machinery, or several of these stacked. The same bar holds wherever a defect gets filed or fixed.

- Design spec: before UI builders run, the brief must carry the approved mockups and build spec (`${CLAUDE_PLUGIN_ROOT}/references/design-spec.md`). A **named gap** in the builder's return goes to the **PM** with the token name it would need — not to a seat.
- Tests: **first coverage is the builder's**, written test-first during the build (Step 3) — so for a behavior seat the work already arrives tested, and this gate reads the coverage rather than commissioning it. Spawn `test-writer` for what that doesn't reach: an **exempted** seat's output, coverage sweeps and fan-out across many files, repairing a red or flaky suite, and any repo whose testing conventions still have to be discovered from scratch. Either way, see the counts yourself, from a run scoped to the slice's changes — a builder's "tests pass" is a narrative until you have; a full suite runs only when the user asks, and a long run is dispatched, not run inline.
- **Comment pass (lead-owned).** On inline edits and on any path where no review seat ran, read the diff's added comments against `skills/roster/shared-blocks.md` → Block I before Step 5.
- **Send work back to builders** when evidence or tests fail — same grouping rule as the original slice (*Group the change's files by seat*, Step 3). Max 2 rounds per seat; then surface what the PM would notice and file the rest. A remainder the PM wants fixed is a new slice, never a third round.
