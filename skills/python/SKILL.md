**Python's dangerous failure is the one that passes the gate and stays quiet.** `ruff` proves style, `mypy` proves the annotations agree with each other, and every trap below survives both — shipping as corrupted data, an invisible skip, or a distribution that imports nothing. Three consequences drive the file: an annotation is a *claim*, not a check (nothing at runtime enforces `-> int`) · a falsy value is a *value* (`0`, `False`, `""`, `[]` are data, not absence) · a green tool run proves the tool ran, never that it looked at your code. That last one is **vacuous** — a pass that could not have failed — and it is the word for the whole class.

Reproduced on **Python 3.14.3** (`darwin/arm64`, 2026-09-02) with **ruff 0.16.5**, **mcp 2.1.1** and **hatchling** via `uv build`, unless a line says otherwise. Behavior gated on a library version follows what the lockfile pins, not what the docs show — check it before reaching for anything marked with a version.

## The gate lies about what it checks
- **A rule in `select` is not a rule that fires.** Ruff's `dummy-variable-rgx` defaults to `^(_+|(_+[a-zA-Z0-9_]*[a-zA-Z0-9]+?))$` — *any* leading-underscore name, not just `_`. So `F811` (redefinition of an unused name) ignores every private helper in the codebase: two module-level `def _is_rate_limited` in one file pass `ruff check --select F811` clean; rename both to `is_rate_limited` and it fires immediately. The dead first copy is the one people then patch. Fix in config — `dummy-variable-rgx = "^_$"` — and accept the trade it names: `_unused = compute()` now trips `F841`, which is real noise in a codebase leaning on `_name` throwaways. Delete the assignment rather than reverting the regex.
- **`ruff check` and `ruff format --check` are different tools.** The linter passing says nothing about formatting. Both run in the gate or formatting drift ships. Keep `requires-python` and `[tool.ruff] target-version` in sync, or ruff applies upgrade rules for a version you don't support.
- **A `lint` target that runs `--fix` is not a gate.** It mutates the tree and exits 0, so pre-existing violations sit on the branch until CI's read-only run goes red. `--fix` belongs in `format` and the pre-commit hook only, and the local target runs the *exact* commands CI runs, over the *same paths* — a narrower local scope is where violations accumulate.
- **Before trusting a check to protect something, write the violation on purpose once and watch it get reported.** Same discipline as seeing a regression test go red: a rule you have never seen fire is a rule you are assuming.
- **`pytest` with zero collected tests is vacuous**, and so is a marker filter (`-m "not integration"`) that deselects the only meaningful ones. Check the collection count, and reproduce CI's exact marker expression locally before reading green as coverage.

## Failures that look like success
- **`x = x or default` eats legitimate falsy data.** `config.get("start_hour") or 9` turns a valid `0` (midnight) into 9; `if self.max_drawdown:` silently disables a limit set to `0`. Guard on `is None`, not truthiness. The one safe use is an empty *container* (`items = items or []`); for numbers, booleans and strings it is a bug.
- **A `return` or `continue` inside `except` that produces normal-looking output is where silent corruption lives.** When you catch, either recover meaningfully or make the failure visible — raise, log at error level, or return a *distinguishable* sentinel.
- **A non-zero exit is not a failure, and stderr is not the output.** Linters, mutation testers and auditors exit non-zero *by design* and write their real summary to stdout. Reproduced: a subprocess printing `3 findings` and exiting 1 has `stderr == ''`, so the `f"Error: {result.stderr}"` wrapper reports a successful run as the string `"Error: "`. Return `returncode`, `stdout` and `stderr` and let the caller judge.
- **The error path writes a terminal state of its own.** `status = "READY"` in both the `try` and the `except` makes failed runs indistinguishable from complete ones; give the failure a value the caller can branch on.
- **A failed fetch propagates, or returns a sentinel the caller renders as an error.** The alternative ships invented numbers that look exactly like measured ones: `except RequestError: return generate_sample_data()`.
- **Partial results returned as complete.** A paginated fetch that `break`s on error returns 12 items whether that is all 12 or 12 of 900. Return completeness alongside the data, or raise.
- **Batch loops: collect per-item errors, never a bare `continue`.** A silent skip gives no way to know coverage was incomplete, and makes sibling operations inconsistent when one reports errors and the other doesn't. Accumulate `{"file": f, "error": str(e)}` and return the list.
- **The exception's type carries the information; `str(e)` keeps only the sentence.** Collapse them and every distinct failure reads the same, with the traceback gone.
- **An empty post-filter rule set is a configuration error, not a clean pass.** Scoring code that maps `results == []` to `score = 100` turns an unsupported request into a silent perfect score. Raise on "no applicable rules", and assert `rules_evaluated > 0` in the test.

## Determinism is a correctness property, not a nicety
- **Iterating a `set` is randomized per process.** `str` hashing is seeded per interpreter run, so three consecutive processes list the same five strings in three different orders. A regenerated file is the same data reshuffled and the real change drowns in the diff. `sorted()` before you serialize; `json.dump(..., sort_keys=True)`.
- **Two RNGs need two seeds.** A library drawing from both `random` and `numpy.random` is half-deterministic if you seed one. And seeding the *globals* (`random.seed`, `np.random.seed`) clobbers the caller's state — take a seed and thread local generators (`random.Random(seed)`, `np.random.default_rng(seed)`) through instead.
- **Locale-dependent parsing.** `datetime.strptime` with `%b`/`%a` reads month and day names through the machine's locale; pin the format and the locale or the test that passes on your box fails in CI.

## Names, imports and construction
- **A package shadows a module of the same name.** Ship both `foo.py` and `foo/` and `import foo` resolves to `foo/__init__.py` — reproduced: `foo.__file__` points at the package and `hasattr(foo, "main")` is `False`, so a console entry point `foo = "foo:main"` fails while running the file directly still works. Pick one name, usually the package.
- **An `__init__` that builds a resource most callers never read is paid by every caller.** The cheap method profiles as free and still takes the constructor's time, because the cost is spent before the body runs. Defer with `functools.cached_property`, or an explicit `None` slot when you also need to reset or pre-populate it. Only safe when construction has no ordering-relevant side effect — opening a file, binding a port, registering a handler is an *operation*, so give it a method name.
- **One factory that builds the whole family makes every cheap path pay for the expensive one.** Split by what the path actually needs, and state which helpers are pure and which require the initialized model — that boundary is what the next change violates.
- **Load-and-unload per call is not a cache.** Cache the handle for the process lifetime; that is what makes an eager `__init__` inside the cached object permanently expensive, which is why the two techniques are a pair.
- **Measure the first call of a fresh process, one entry point at a time** — in-process timing after the first call measures nothing. Then tell a one-time import from a repeated load: `python -X importtime -c "import mypkg"`, and re-time the same call in the same process (an import drops to near zero, a per-call load does not). `tracemalloc` around one construction is the memory half of the argument.

## Async, threads and the boundary
- **Making a field lazy changes when `@patch` binds.** A patch on a constructor called in `setup_method` did *nothing* while the field was eager — the real object was already built. Once it is lazy, the patch is consulted at first use and finally takes effect, so tests keep passing while quietly switching to assert against a mock. Re-read every test that patches a constructor you just deferred.
- **A connection is opened and closed on the thread that uses it.** Building a SQLite connection on the event-loop thread and handing it to a worker trades event-loop starvation for intermittent database errors — the wrapper looks like a fix and moves the failure.
- **`shlex.split`, never `str.split`, for an argument string** — reproduced: `'--name "two words" -v'.split()` yields `['--name', '"two', 'words"', '-v']`. Pass an argv list to `subprocess.run`, never `shell=True`, and never interpolate a caller-supplied string into a shell command.
- **Rich traceback renderers can print every frame's locals** — API tokens, auth headers, request bodies. `rich.traceback.install(show_locals=False)` anywhere logs leave the machine, and test it by driving `sys.excepthook` with a sentinel string rather than asserting the config call.
